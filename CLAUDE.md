# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A channel-agnostic "customer comms" service: a templating REST API that builds personalised customer messages, plus a single-page frontend that renders one of them. The requirements live in `backend/README.md` — read them before implementing anything. Prioritise readability and strong typing. The code must compile and run on Node 18+, but Next 16 needs Node 20.9 or later, so the repo pins Node 22 in the root `.nvmrc`. Keep scope tight: no auth, database, containerisation or other unrequested infrastructure.

This is a single git monorepo at the root. `backend/` and `frontend/` are independent yarn projects, each with its own `package.json`, `yarn.lock` and `.gitignore`, and there are no yarn workspaces. Run yarn commands from inside each directory.

## Backend (`backend/`) — NestJS 10

```bash
yarn start            # runs on http://localhost:3001
yarn start:dev        # watch mode
yarn build            # nest build -> dist/
yarn lint             # eslint --fix over src/test
yarn format           # prettier
yarn test             # jest, rootDir=src, matches *.spec.ts
yarn test src/path/to/file.spec.ts        # single file
yarn test -t "name of test"               # single test by name
```

- Still the Nest starter skeleton (`AppModule` / `AppController` / `AppService` with a hello-world route). New features go in their own Nest modules, registered in `AppModule`.
- `data.json` (~500 customers) stands in for the database: read from it, don't add a DB. Shape: `{ id, firstName, lastName, email, cats: [{ name, subscriptionActive, breed, pouchSize: 'A'..'F' }] }`. It was generated by `.tools/create-fake-data.ts` (uses `@faker-js/faker`, which isn't a dependency). Every customer's first cat is active; later cats may be inactive.
- `main.ts` doesn't enable CORS yet. The frontend runs on a different port, so browser calls from it will fail until CORS is enabled or the frontend proxies the calls.

### Required endpoint: `GET /comms/your-next-delivery/:userId`

Returns `{ title, message, totalPrice, freeGift }`. Rules that are easy to get wrong:
- Only cats with `subscriptionActive: true` count, both for the names shown and for the price.
- Cat names: `A`, `A and B`, `A, B and C` (Oxford comma not used).
- Price = sum of active cats' pouch prices: A 55.50, B 59.50, C 62.75, D 66.00, E 69.00, F 71.25 (GBP).
- `freeGift` is true when the total is **over** £120 (strictly greater).
- Worked example in the README: user `ff535484-6880-4653-b06e-89983ecf4ed5` gives "Dorian and Ocie" and `totalPrice` 134.00, with `freeGift: true`.

## Frontend (`frontend/`) — Next.js 16 App Router, React 19, Tailwind v4

```bash
yarn dev      # http://localhost:3000
yarn build
yarn lint
```

- This Next.js version has breaking changes compared with older releases. Check the bundled guides in `frontend/node_modules/next/dist/docs/` before using Next APIs rather than relying on memory.
- If `next dev` is started by an AI agent, it recreates `frontend/AGENTS.md` and `frontend/CLAUDE.md`. The project doesn't use them, so delete them if they appear.
- Still the `create-next-app` template. The app is a single route, `/welcome/[userId]`, that calls the backend endpoint above and renders the message in the style of the linked Figma design. The layout only needs to be roughly similar, and any cat image will do.
- No test runner is configured.
